## Decisions

- Migration is `0020_task-033-identity` (range 0020-0029), generated by `pnpm db:generate`. Grants appended: `users`, `invitations`, `access_requests` SELECT/INSERT/UPDATE/DELETE and `platform_settings` SELECT/INSERT/UPDATE for `app_api` and `app_worker` (erasure runs in the worker; the settings row is never deleted).
- Token verification is one RS256 verifier (`jwt.ts`, `node:crypto`) shared by the Clerk adapter and the local fake, with its own 10-minute key cache: the `@clerk/backend` JWKS cache TTL option is a no-op (deprecated) in 3.29, so the adapter loads keys through `client.jwks.getJwks()` and caches them itself. An unknown `kid` refreshes the key set at most once a minute.
- A third typed error, `IdentityTokenInvalid` (bad, expired or foreign token: 401), is added beside `IdentityUnavailable` and `IdentityNotFound` so a bad token is never confused with an outage.
- `revokeSessions` for an unknown subject succeeds (the provider answers an empty list); `deleteUser` and `revokeInvitation` say `IdentityNotFound`.
- `IDENTITY_MODE` is read from the process environment in `identityConfigFrom` (unset: `local` away from staging/production, `clerk` there; `local` refused when hosted). The registry row still says `pending:TASK-033`; moving it into `platform/config` is a change request.
- The placement `apps/api/src/modules/identity/index.ts` is not in the allowed paths, so the module's public exports live in `identity.module.ts` (importable by other modules); the Orchestrator may want an `index.ts` for the next identity tickets.
- Files outside the allowed paths that had to change (Orchestrator to confirm): `apps/api/vitest.config.ts` and `apps/api/package.json` (junit and lcov copy for `reports/identity`, coverage include; the Drizzle repositories, module wiring and test double are excluded from unit coverage and proven on real PostgreSQL), `apps/api/src/platform/http/edge.test.ts` (the production-APP_ENV boot now provides the two Clerk keys the Clerk adapter requires), `apps/api/tests/integration/audit/audit.integration.test.ts` (ledger count 2 to 3).
- `pg_dump` is needed by the TASK-025 suite (`PG_CLIENT_ROOT`, here `/tmp/pgroot`).
