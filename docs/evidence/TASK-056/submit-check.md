# TASK-056 evidence

- `reports/deps.sarif` is read in place of the `reports/deps.json` the ticket names (as in TASK-044, TASK-053, TASK-054 and TASK-055).
- Each pnpm script is its own `--check`, run with `CI=1`. The real FFmpeg binary was the pinned static LGPL build of `docker/Dockerfile` (n7.1.5, sha256 checked), unpacked outside the repository and found through `FFMPEG_DIR`; the integration suite falls back to fake `ffmpeg`/`ffprobe` scripts only on a machine that has neither.
- Files: `application/worker/assembly-ports.ts` (AssemblyPort, config, errors), `assembly-render.job.ts` (the handler), `assembly-recovery.ts` (the sweep hooks), `infrastructure/ffmpeg/assembly-ffmpeg.ts` (the adapter), `production.module.ts` (wiring, `assemblyWorkerConfigFrom`), `bootstrap/worker.module.ts` (the `assembly` resolver, one import name and one line). Outside the listed paths, as in every earlier production ticket: the `prod-ffmpeg` junit/lcov entries in `apps/api/vitest.config.ts` and `apps/api/package.json` that the ticket's `--junit` and `--coverage` flags name.
- Design: the claim moves `pending`/`queued`, or a working state whose lease ran out, to `fetching` with a new lease and `attempts + 1`; `attempts` fences every later write, so a run that lost its lease cannot move the job. A heartbeat renews the lease. A killed worker leaves a working state with an expiring lease; the next run (the queue retry, or the sweep hook `production.assembly-resume`) restarts from `fetching`. The output key is the job's own, so the resume registers the object that is already there: one output. `attempts` is limited to 3, then `render_failed` ("interrupted too many times"). A fault that retrying cannot fix (bad clip, ffmpeg error, timeout) ends the job `failed` with its cause class and a fixed message; anything else is thrown, the lease is released and the queue retries.
- `ASSEMBLY_ADAPTER=shotstack` stops the worker at start-up (OD-08: only ffmpeg is built). The opening frame is supported by the adapter (proved with the real binary); the worker passes none until M0012 creates thumbstopper jobs (API-070 refuses a thumbstopper ID until then).
