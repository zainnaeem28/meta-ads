- `reports/deps.sarif` and `reports/audit.json` are read in place of the `reports/deps.json` the ticket names (as in TASK-044, TASK-053, TASK-054 and TASK-055); `scripts/ci/deps.sh` writes those two.
- Each pnpm script is its own `--check` (`lint`, `typecheck`, `test:unit`, `test:integration`), run with `CI=1`, plus `scripts/ci/layers.sh`, `contract.sh`, `sast.sh`, `deps.sh` and `secrets.sh`.
- Migration `0110_task-057-production-thumbstopper.sql` (CLI-generated with `pnpm db:generate --name=0110_task-057-production-thumbstopper`; the grants block is appended). It creates `thumbstopper_jobs` on the provider-job column contract (SB §3.5), with the partial unique reuse index, and adds the SET NULL foreign key `assembly_jobs.thumbstopper_job_id` that M0011 left as a plain column. Grants: `SELECT, INSERT, UPDATE` to `app_api` and `app_worker`.
- API-075 (`POST /campaigns/{id}/thumbstopper`, job-creating): campaign (owner-scoped, active) → idempotency replay → claim engine over `calloutText` (422 `open_claim_issues`, `details[].field = calloutText`, `details[].code` = rule ID) → live-job reuse → OpenAI key (`key_missing`, `key_disabled`) → spend cap with the reservation (`spend_cap_reached`) → row + queue message `production.thumbstopper-submit`, all in one transaction. API-076 returns the newest job, or `data: null`.
- The claim engine is the brief module's (`checkSegment` over the active `brand_rules`). Only the free-text rule kinds (`phrase`, `regex`, `em_dash`) judge a call-out; the structural kinds (word count, call to action, age framing) judge a script and would refuse every short call-out.
- Worker: `ThumbSubmitJob` (key gate, claim, one image call, guard after put), the `ImageGenPort` OpenAI adapter (`/v1/images/generations`, 120 s, portrait 1024x1536, response read as base64 and type-sniffed: only PNG, JPEG or WebP is stored, size-capped by `PROVIDER_OUTPUT_MAX_BYTES`), `ThumbRecovery` sweep hooks (requeue, orphaned `submitting`, expired `pending`). The image is stored under `u/{owner}/c/{campaign}/thumbstopper/{id}.{ext}` and registered as a `thumbstopper` media row (private: only a signed URL reads it). The cost is the price-table row of `OPENAI_IMAGE_MODEL` (`local-stub-image` 0.04 USD in `config/price-table.json`), reserved at creation and recorded as a usage event by the job.
- Outside the listed paths, each the smallest change the ticket needs: `apps/api/src/modules/brief/index.ts` (appends exports of `BrandRulesReader`, `checkSegment`, `compileRules` and two types, so production reads the claim engine through the brief module's index as the layer rule requires); `apps/api/src/database/schema/production-assembly.ts` (the M0012 foreign key on `thumbstopper_job_id`); `apps/api/vitest.config.ts` and `apps/api/package.json` (the `prod-thumb` junit/lcov entries the ticket's `--junit` and `--coverage` flags name, as in every earlier production ticket); `bootstrap/worker.module.ts` (the `ThumbSubmitJob` import and its queue handler entry).
- Limits left to other tickets, stated plainly: API-070 still answers 404 for a non-null `thumbstopperJobId` (`assembly.service.ts` is outside this ticket's paths; the foreign key now exists, so the check can be made real there); campaign deletion and account suspension call `VideoJobsService.cancel*` only, so `ThumbService.cancel` (written and exported, owner- and campaign-scoped, releasing reservations) is not yet called by the lifecycle module (`lifecycle` is outside the paths). A thumbstopper job of a deleting campaign is not sent (the worker skips it) and goes with the campaign cascade.
