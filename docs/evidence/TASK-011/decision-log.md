# TASK-011 decision log

| # | Question | Choice | Reason |
| --- | --- | --- | --- |
| 1 | Language and runtime of the script | TypeScript run by Node 24 type stripping (`node src/main.ts`), dependencies `@aws-sdk/client-s3` and `pg` only | The base image is already Node; no build step; the image needs no application code. The image adds the PostgreSQL client (PGDG, key pinned by checksum, major version `PG_MAJOR`, 17 to match the test server) and Debian `age` |
| 2 | How the dump is encrypted | `pg_dump` stdout piped into `age --recipient`, written to a spool file, then a conditional put | The plaintext dump never touches disk; the service holds only the public recipient (SB v6 §7.1 D) |
| 3 | Password handling for `pg_dump` | URL split into `PGHOST`, `PGUSER`, `PGPASSWORD`, … in the child's environment only | No password in `argv` or in logs |
| 4 | Dump scope flags | `--format=custom --schema=public --schema=pgboss`, owners and ACLs kept, no `-j`, row security left off | SB v6 §7.1 A, B, E; a restore verifies roles and grants, so they stay in the archive. A scan test fails if the row-security option is ever added |
| 5 | Spool before upload | Media and dump are written to `BACKUP_SPOOL_DIR`, checked (size, MD5 when the ETag is a plain MD5), then put | A damaged read must never become a content-addressed object under a name that makes every later run skip it. Cost: disk for the largest object |
| 6 | Manifest identity | One manifest per day `manifests/<date>.json`; a second run the same day writes `manifests/<date>-<runId>.json`; the previous state is the newest manifest by upload time | Nothing is overwritten; ordering by key would put the suffixed name before the plain one |
| 7 | What counts as deleted | A source **key** absent from the `u/` listing. A key that now has another etag is "superseded": the old content stays in `media/`, untouched (TC-BKP-19) | Deleting superseded content is not in SB v6 §7.1 C and the service's only delete must stay narrow |
| 8 | Retry date of a failed delayed delete | After a failed confirmation the next retry on a later day uses that day in `media-deleted/<date>/`; the same day it fails again | A damaged copy under the lock cannot be replaced, so its key must not be reused; the lock clock of the new copy starts at its upload anyway |
| 9 | Release-migration signal | Session advisory lock `release-migration` (`hashtextextended('release-migration', 0)`, the naming `lockXact` uses) **or** any other session holding Share, Share Row Exclusive, Exclusive or Access Exclusive on a `public`/`pgboss` table. Waits up to `BACKUP_MIGRATION_WAIT_SECONDS`, then exit 75 | No migration lock key existed in the code. The DDL signal needs nothing from the migration owner; the advisory lock is the explicit contract and is **a follow-up for the `migrate` step owner** (take that lock for the whole run). `pg_locks` is readable by `app_backup` |
| 10 | Heartbeat | Pinged only after a run in which every step succeeded; three attempts | A partial run must not hide behind a green heartbeat (ALR-6 at 26 h) |
| 11 | One credential for source and sink | Refused, except in `development` and `test` with `BACKUP_ALLOW_SHARED_TOKEN=1` | The local MinIO has one root user; hosted environments need two tokens (SB-D20) |
| 12 | Emulator for R2 | In-memory S3 server in `tests/support/s3-emulator.ts` (token scopes, age and indefinite locks by prefix, conditional put, lifecycle model, clock, fault hooks), plus a real MinIO for the end-to-end run | MinIO cannot express R2's two-token scope or lock rules, and no `mc` is available to script users. The emulator proves the script's behaviour only; the real R2 behaviour is TC-H-15 |
| 13 | Lock verification | `src/verify-locks.ts`, run once by the owner with the sink token; exit 3 and `BLOCKING (DO-07)` lines when any probe is accepted | "If the host offers no lock, raise a blocking finding": the check makes that mechanical. The service never sets a rule |
