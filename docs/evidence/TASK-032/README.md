## Decisions

- Migration is numbered `0010_task-032-audit` (range 0010-0019), generated by `pnpm db:generate`.
- `raiseAlert` cannot observe the caller's commit (the unit of work has no commit hook), so it returns a `PendingAlert`; the caller invokes `announce()` after its transaction resolves. A duplicate open alert returns `raised: false` and announces nothing.
- The `admin_alert` line carries `code` (kind), `userId` (subject) and `jobId` (alert ID): the log allow-list drops other fields, so counts are never logged.
- Alert timestamps are read as text (microseconds) so a list position compares exactly.
- Grants: `audit_events` SELECT, INSERT; `admin_alerts` SELECT, INSERT, UPDATE; `app_backup` reads both through the M0001 default privileges.
- Files outside the ticket's allowed paths that had to change (the Orchestrator should confirm): `apps/api/vitest.config.ts` and `apps/api/package.json` (junit and lcov copy for `reports/audit`, coverage include for the audit domain and service; the Drizzle repository, module wiring and ports file are excluded from unit coverage and proven on real PostgreSQL), and the TASK-025 grants suite (`renderMigrations(env, 1)`) which scaffolds stand-in `audit_events` and now applies only M0001.
- `pg_dump` is needed by the TASK-025 suite (`PG_CLIENT_ROOT`).
